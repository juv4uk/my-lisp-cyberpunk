# Тести диспетчера на my-lisp

Запуск із кореня цього репозиторію канонічним інтерпретатором:

```powershell
& C:\GitHub\my-lisp\target\release\my-lisp.exe tests/диспетчер.лісп
```

Успіх: `t` та exit code 0. Порушення твердження спричиняє Lisp error і ненульовий exit code. Мінімальна функція `перевірити` використовує помилку `car` на текстовій назві тесту, бо окремий assertion API тут не вводиться; це не нова семантика мови.

Тест читає справжній `scripts/dispatcher.lisp` через `read-file` / `read-all` та виконує його через канонічний `eval`. Перевіряє відсутність, появу, повторний кадр, заміну та зникнення гравця. Підставні capabilities задають лише факти. Заборонений виклик класу без гравця завершує тест помилкою.

Тести не доводять доставку F10, правильність C++ handles, FFI, UI або паритет embedded runtime з канонічним інтерпретатором. Вони доводять поведінку Lisp-диспетчера над заданими фактами. Символи першого й другого гравця — тестові значення, а не модель opaque handle.
