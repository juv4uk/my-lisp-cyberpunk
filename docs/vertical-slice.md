# Перший вертикальний зріз: `(запиши-лог)`

## Що саме доводить зріз

Після завантаження RED4ext викликає `Main(..., Load, ...)`. Адаптер:

1. знаходить свою директорію;
2. завантажує `wsm_my_lisp_cyberpunk_dll.dll` через `LoadLibraryW`;
3. створює Lisp-сесію через `wsm_session_init`;
4. реєструє host-примітиву `запиши-лог`;
5. обчислює український вираз `(запиши-лог)`;
6. записує у RED4ext log виклик примітиви та надрукований Lisp-результат.

Це доводить повний напрямок `Lisp → host adapter → Lisp` у процесі гри.
Примітива приймає нуль аргументів і повертає `()`; вона не отримує жодних
RTTI-посилань і не має доступу до save/inventory/player state.

## Очікувані рядки логу

```text
my-lisp-cyberpunk: Lisp host primitive запиши-лог invoked
my-lisp-cyberpunk: (запиши-лог) => ()
my-lisp-cyberpunk: wsm_my_lisp_cyberpunk_dll.dll loaded, session=...
```

Порядок перших двох рядків фіксований, останній вказує на успішне
створення сесії. Значення адреси після `session=` не є частиною фікстури.

## Відомі межі

- `TAG_BOXED=7` досі очікує ратифікації в `wsm-target-contract`; цей зріз
  не передає рядків через FFI і від нього не залежить.
- Усі числа tagged-word ABI повинні надходити з `wsm-target-contract` після
  його ратифікації. Поточне `()` повертається відповідно до наявного
  експериментального WSM ABI.
- Реальний запуск потребує окремого smoke test на встановленій грі та
  RED4ext. Успішна CMake-збірка цього не доводить.
